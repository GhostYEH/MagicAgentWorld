# AgentCraft：精简技术规划

版本：规划 v2.0。日期：2026-10-10。C1/C2 已接入 Phaser 游戏；后四章将转为 Agent 预算诊断与修复任务，当前旧引擎样例只作历史回归。

## 一、技术选择

| 模块 | 首版方案与职责 |
| --- | --- |
| Web 工程 | TypeScript + Vite：编译与本地素材；原生控件处理中文输入 |
| 游戏场景 | Phaser：校园地图、角色移动、交互热点与任务反馈 |
| 界面状态 | GameState 与 Phaser 场景事件：进度、配置、面板 |
| 样式与动画 | Phaser HUD / Graphics / Tween；输入层使用普通 CSS |
| 执行内核 | 共享 TypeScript：世界、工具、循环、限制和核验 |
| 服务端 | Node.js + Fastify：真实模型运行、参数校验、记录 |
| 存储 | 浏览器 IndexedDB 存档；服务端 SQLite 保存运行与事件 |
| 验证 | Vitest 测引擎规则；Playwright 验证六章操作与离线演示 |

这套方案让界面、游戏和运行规则共用 TypeScript。Phaser 是 2D 引擎，2.5D 效果采用等距素材与前后遮挡实现。首版用可复现模拟决策器，随后接一个真实模型；分词使用固定版本的实际分词器，资产本地加载。建项时选择兼容版本并锁定依赖。

依据：[Phaser 官方说明](https://docs.phaser.io/phaser/getting-started/what-is-phaser)、[Fastify 文档](https://fastify.dev/docs/latest/)、[SQLite 使用场景](https://www.sqlite.org/whentouse.html)。

## 二、模块边界与接口

Phaser 场景接收操作，HUD 与世界场景通过事件通信。任务世界状态及成功判定由运行引擎维护；GameState 保存探索和界面状态。动画播放速度不改变任务的虚拟时间。

模拟模式在浏览器执行，真实模式由服务端执行；共用工具、世界与核验规则，通过统一运行适配器返回事件。真实密钥仅在服务端，浏览器提交的“成功”不能代替服务端核验。

目录如下：

```text
apps/web/          Phaser 世界、游戏 HUD、原生输入、本地存档
apps/server/       Fastify、模型适配器、SQLite
packages/engine/   运行类型、世界、工具、循环与核验
packages/content/  六章任务、公告、故障及讲解配置
```

运行输入包含 chapterId、taskVersion、mode、seed、prompt 和 harnessConfig。事件包含 runId、seq、step、type、payload；界面按序去重，切换运行后忽略旧事件。场景卸载时清理监听器与游戏实例。

真实模式最小接口：`POST /runs` 创建运行，`POST /runs/:id/control` 单步/暂停/继续/取消，`GET /runs/:id/events` 用 SSE 推送事件，`GET /runs/:id` 读取状态与报告。事件持久化后推送，重连按序号补取。模拟模式提供同样的操作语义。

## 四、工具与任务规则

| 工具 | 用途 |
| --- | --- |
| runtime.inspect | 读取本次教学运行的 Token 预算配置 |
| calculator.evaluate | 精确计算剩余预算，只处理受限数值表达式 |
| documents.retrieve | 检索 Agent 规约，返回正文、来源与版本 |

这三项已用于 C2 游戏。旧 schedule、enrollment 和 library 事务工具保留作引擎回归样例，不出现在当前游戏教学任务中。C3—C6 需先替换任务与决策器，再接入自主执行、记忆修复和摘要核验。

工具只操作虚拟世界。所有调用检查工具名、参数、权限和预算；提交检查前置状态。写操作使用幂等键，重试不能重复提交。资料中的文字不能改写系统权限。

工具定义包含参数 Schema、读/写属性、超时及执行函数。调用依次经过参数校验、允许/确认/拒绝策略、预算检查、执行和结果记录。玩家授权只在关卡允许范围内有效，系统硬约束始终执行。

## 五、最小运行控制

每次决定执行一项行动，支持开始、单步、暂停、继续、取消。暂停在行动边界生效；取消向模型和工具传递 AbortSignal，禁止后续行动与未提交写入。已经提交的事务保留实际状态，迟到回执只归属原运行。

Harness 拆成六个小模块：RunController 管循环与状态，ToolRegistry 管工具及权限，ContextBuilder 管上下文与事实记忆，BudgetController 管预算，RecoveryPolicy 管恢复，EventRecorder 管记录。通过请求前、工具前、工具后、错误时的明确接口组合。

任务上限从关卡配置读取，当前 C2 最多 24 次调用，并允许重置实验；后续自主执行关按实际工具链设定上限。工具失败和重试计步数；模型请求失败、格式修复也计请求次数和预留输出预算，另设超时与运行截止时间。预留预算与实际 usage 分开显示。

同工具、同参数重复时先提醒，结合新事实与任务进展判断无进展；实际硬步数和截止时间不能关闭。DeepSeek 的重复调用提醒属于软引导，其 agent-loop 没有内置整轮预算，不能直接当作防无限循环保证。

上下文按三层组织：目标/规则与选中的事实记忆、近期观察、按需工具检索。压缩记录明确列出保留与遗漏内容，完整日志继续保存。事实记忆关联来源事件与任务版本，不修改模型参数；没有记忆模块也可能成功，按实际结果说明。

只执行模型适配器确认完整、参数有效的工具调用；截断或异常响应留作诊断。暂时故障有限重试，权限/参数错误返回原因。写入结果分已提交、未提交、未知；未知时暂停并查询状态，不能盲目重放写入。

## 六、记录与评分

保存章节 C1—C6、任务版本、模式、输入/配置快照、seed、工具请求与结果、世界终态和核验结果。修改配置后新建运行，同条件便于比较。

运行开始时冻结模型选择、任务与配置。模型可见的输入、工具定义、记忆和上下文变化均留记录，能够还原每次请求；不记录密钥。世界变更与对应事件原子提交，地图、时间线与报告从已提交事件推导。首版恢复限定为当前运行的暂停/继续和失败后重跑。

Token 使用实际分词结果，不能把字数当作精确 Token。实验分词与供应商 usage 分开，未知计量标为未知。模拟生成明确标注规则行为，不冒充真实输出。

任务由独立规则核验；模型声明完成不足以通过。最终比较正常任务、暂时工具故障、有限上下文三种条件，记录通过数/实际测试数、步骤、游戏资源与实际调用消耗。两配置使用相同条件，失败尝试成本也记录。

## 七、开发顺序与验收

按五个交付点推进：① Phaser 世界、HUD 与本地素材；② C1 记忆/输入实验与 C2 工具安装玩法；③ 替换旧题材，再开发 C3 自主行动、C4 装配控制、C5 故障修复；④ C6 挑战、存档与报告；⑤ 真实模型联调与打包。当前 C1/C2 游戏已打通。

Node 服务同时提供构建后的网页与 API，本地演示包附启动脚本和离线运行依赖。在线版使用 HTTPS；模拟演示不依赖外部 CDN、字体或模型服务。

通过标准：六章机制可运行；模拟同条件可复现；故障可解释；参数/权限错误被拒绝；重复写入与取消处理正确；分词和任务资产断网可用。真实模式另留真实输入及工具调用证据。
