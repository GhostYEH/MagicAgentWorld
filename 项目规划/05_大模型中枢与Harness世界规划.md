# AgentCraft：大模型中枢与 Harness 世界

规划 v2.1，2026-10-10。中枢、五处部门建筑与布局及六章循序开放已完成；数据流联动和后续教学机制仍待开发。现有 C1/C2 操作保留，不代表本方案全部教学已完成。建筑交付见根目录 `部门建模说明.md`，区域门禁见 `章节开放说明.md`。

## 1. 核心定位

把智能体的组成做成一座可以探索、组装和调试的动漫城市。玩家是智能体工程师，AC–01 是被组装的实验伙伴。

教学采用宽泛的工程表达：**Agent ≈ 大模型 + Harness**。大模型负责读取当前输入、生成回答或提出工具调用；Harness 围绕模型组织上下文、执行工具、保存状态、控制循环、权限与预算，并记录和恢复运行。目标从任务入口进入，工具连接可操作的环境。

这里的“组装”不修改模型权重。工具不会由模型的文字直接执行，持久记忆也不会自动成为模型当前可见信息。两者必须经过 Harness 接入与调度。

## 2. 地图：一个中枢，五处运行设施

保留电脑端、日系动漫、2.5D 等距、连续地面与人物跟随镜头。主路围绕中心布置，短支路进入五处设施；建筑有实际入口、底座与遮挡。

| 位置 | 建筑与造型 | 必须看见的知识 | 代表操作 |
| --- | --- | --- | --- |
| 正中央 | **大模型中枢**：最高的蓝玻璃穹顶，内部发光核心，入口显示 LLM | 读取当前上下文；生成回答或下一项工具请求 | 修改 Prompt、移出证据；比较回答、依据与 Token |
| 西侧 | **工具工坊**：机械臂、三种能力插槽 | 工具定义 → 参数 → 执行 → 回执 | 安装检索、计算、导出工具；检查实际结果 |
| 西北侧 | **执行循环塔**：环形轨道、逐步点亮的节点 | 模型决策 → 工具执行 → 观察 → 再决策 → 停止 | 从玩家手动调用切到自主选择；单步/连续/停止 |
| 东北侧 | **上下文与记忆馆**：玻璃工作桌与档案柜 | 当前上下文、持久记忆、检索加载各有职责 | 保存证据，再选择哪些内容进入下一次请求 |
| 东侧 | **运行控制塔**：闸门、时钟与资源刻度 | 权限、步数、Token、超时决定行动边界 | 调整授权与预算；观察拒绝、暂停和预算停止 |
| 南侧 | **观察与修复站**：回执终端、警示灯与维修台 | 输入、调用、结果、错误、恢复构成可追溯记录 | 定位错误参数、无进展或证据遗漏，再修复重跑 |

中央建筑占地和高度明显大于其他建筑，是全图第一视觉焦点。其余五处具有不同轮廓，保持同一配色、材质、描边和投影。中央门前设小型 **Agent 总装台**，用于查看整套配置与挑战结果。

花箱、旗帜、树木作为陪衬；主要装饰采用工具插槽、记忆档案、数据管线、运行指示灯和回执终端，能解释其所在设施的用途。旧宿舍等生活建筑退为背景，避免抢占教学主线。

## 3. 知识必须出现在世界里

每处设施只呈现三个层次，控制文字量：

1. **路过能懂**：建筑名 + 一句职责 + 一个流程符号。例如“上下文：模型本次能看到的信息”。近景和总览均有可读的职责标签。
2. **操作能看到变化**：卡片进入请求槽、工具收到参数、回执沿管线返回、预算刻度下降、闸门阻止未授权行动。长解释按需展开。
3. **出错能理解原因**：指出哪一步缺了证据、参数为何错误、循环为何停止；玩家改一个配置，再比较结果。

世界展示的数据流为：**目标 → Harness 组装上下文 → 大模型 → 行动请求 → 权限/预算检查 → 工具执行 → 回执记录 → 更新上下文 → 大模型继续或停止**。

这条流程使用真实运行事件驱动。模型生成文字亮起中枢；提出调用后亮起工具工坊；执行结束才出现回执；预算耗尽或核验结束才显示停止。动画速度不改变执行结果，支持暂停与减少动态效果。

## 4. 六章围绕同一个 Agent 逐步展开

| 章节 | 操作与学习成果 |
| --- | --- |
| C1 模型觉醒 | 在中枢对比有证据/缺证据、不同 Prompt 与 Token；认识模型读取和生成的边界 |
| C2 工具解锁 | 在工坊手动安装并调用工具；区分工具请求、实际执行和结果回执 |
| C3 Agent 诞生 | 启用循环塔，同一个目标改为系统自主选择工具；看到观察如何改变下一步 |
| C4 Harness 工坊 | 在记忆馆和控制塔改一项配置；同模型、同目标下比较上下文、权限和预算的影响 |
| C5 失控与修复 | 根据修复站的真实记录定位一处故障，修改配置并重跑验证 |
| C6 智能体挑战赛 | 在总装台独立配置 Agent，完成新条件下的任务，比较正确性、来源、调用次数和成本 |

统一贯穿任务：**让 AC–01 从给定资料中生成一张有来源的 Agent 知识卡**，包含“大模型的职责、执行循环、可靠运行所需的控制”。资料读取、必要计算与卡片导出均通过工具；同一任务逐章加入自主执行和运行控制。

初始只开放中枢实验。每接入一项能力，建筑状态、连线和 Agent 配置同步变化。最终展示整座城市共同运行，体现为什么同一个模型在不同 Harness 下表现不同。

## 5. 开发顺序与验收

第一阶段：先重排地图，做中枢与五处差异化设施、常驻职责标签和可读流程。保留现有移动、碰撞、缩放和遮挡，暂不扩展新教学功能。

第二阶段：完成一条最小闭环——中枢读取输入、提出一次调用、工坊真实执行、回执进入下一次上下文。先证明场景事件与实际记录一致，再扩展循环。

第三阶段：接入上下文/记忆、权限/预算与修复实验，完成六章核验与配置对照。复用 Phaser、TypeScript 与现有运行内核；旧报到引擎样例需要替换任务与决策器后才能使用。

模拟模式明确标注，真实模型联调另行验收。学习通过由实际结果和理解题共同判断，人物走到建筑、模块亮起或模型宣称完成都不能替代核验。

验收：截图能辨认“大模型在中心、Harness 在周边”；默认画面能读到职责；一次调用的请求/执行/回执可区分；禁用某项能力后能观察相应影响；所有入口可达；仅电脑端。

## 6. 15 分钟介绍路线

1 分钟看城市组成；2 分钟看模型边界；2 分钟接工具与回执；2 分钟开启自主循环；3 分钟对比记忆、权限和预算；2 分钟故障修复；1 分钟总装挑战结果。正式内容 13 分钟，预留 2 分钟缓冲，实际时长待彩排。
